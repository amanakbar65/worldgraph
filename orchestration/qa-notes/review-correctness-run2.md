- **[major] One panel's failure or a cancelled call turns the app-wide data status into an error** (shell; frontend/src/api/client.ts, frontend/src/api/sources/connector.ts)
  - Evidence: LiveWithSnapshot and Tracked set useConnection to {status:'error'} for every DataError (client.ts:48, 65), and StatusBar prints reason.message. Opening #story=story:does-not-exist on the web: the globe and top loaded fine, but the bottom-left pill changed from 'Sample data' to '⚠ Not found: story:does-not-exist' (shots/_story_story_does_not_exist-dark-1440.png; same with #region=region:zz). In the test link, toDataError maps the shell's 'cancelled' code (an aborted AbortSignal, types/mcp.d.ts) to a retryable 'unavailable' DataError (connector.ts:207). The throwaway vitest test-results/review-correctness/cancel.test.ts shows one aborted call leaves the state as {status:'error', reason:'The call was cancelled.'}. react-query aborts in-flight queries whenever a panel or window changes, so ordinary fast navigation flips the pill to a warning.
  - Fix: In ConnectorSource, rethrow a cancelled call as an AbortError (new DOMException('Aborted', 'AbortError')) instead of toDataError. In client.ts, only set the global 'error' state for transport-level kinds (unavailable, offline, connector_*), never for server_error, bad_response or 'Not found' messages; those belong to the panel's own ErrorState.

- **[minor] Not-found answers come back as HTTP 500, are classed 'unavailable' and retried** (netlify; frontend/server/rpc.ts, frontend/src/api/sources/http.ts)
  - Evidence: handleRpc returns status 500 for every SQL exception, including 'Not found: …' and argument errors (rpc.ts:53-54). HttpSource maps ≥500 to a retryable 'unavailable' (http.ts:36), so the query client retries once.
