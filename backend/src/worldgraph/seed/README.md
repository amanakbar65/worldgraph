# Sample data

The sample data makes WorldGraph complete before live data flows. It's invented but realistic, and it's always labelled. `uv run wg seed check` validates everything, and `uv run wg seed load` (or `wg seed sql` for the Supabase connector) writes it to the database, with times relative to *now*.

```
seed/
  gazetteer.json            every country, state/province and major city (Natural Earth; generated by `wg geo gazetteer`)
  entities/
    sectors.yaml            the nine sector lenses
    blocs.yaml              groups of countries (the EU)
    commodities.yaml        traded goods with HS codes and leading producers
    infrastructure.yaml     chokepoints, ports, terminals, mines, industrial zones
    organizations.yaml      real companies and institutions: true background facts only
    policies.yaml           policies and regulations
    indicators.yaml         KPI series (generated from a short description)
  storylines/<id>.yaml      one connected story arc per file
```

## Honesty rules (non-negotiable)

1. **Never invent news about a real company or person.** Real organisations appear only in true background facts (in `entities/`). If a story needs a company, invent one inside the storyline with `sample: true` and a plausible but clearly fictional name (for example "Kestrel Lines"). Public institutions (central banks, OPEC, canal authorities, ministries) may appear in sample events about their normal role, such as a rate decision or output targets. No people at all.
2. **Keep it plausible.** Events follow real mechanisms (freight rates, monsoon, rate decisions). Avoid politically charged or partisan claims: no elections between named parties, no wars between named countries beyond what is already widely reported as an ongoing situation (the Red Sea attacks are fine; a new invented war is not).
3. **No full sentences copied from real articles.** Write everything fresh.
4. **No dates in text.** Avoid "in March" or "2027". Times come from `age_hours` and `end_in_days`, so the data always looks current.

## Writing rules

| Field | Rule |
| --- | --- |
| `headline` | 3–12 words. A plain statement of what happened, in sentence case and present tense, with no full stop. |
| `so_what` | 5–20 words, one sentence, ending with a full stop. Why it matters to a business. |
| `actions` | 0–3 items, each 2–8 words, imperative. "Lock in contract rates before renewals". |
| `mechanism` (links) | 2–4 words, lowercase verb phrase. "raises input costs", "cuts supply". |
| `evidence` (links) | Optional. One sentence starting "Sample evidence:", or omit it and the build writes one. |
| `short_title` (forecasts) | 2–12 words, phrased as a question. |
| `impact` | `risk`, `opportunity` or `neutral`, from the point of view of businesses exposed to it. Aim for opportunities as often as risks. |
| `magnitude` | 1–5: 1 is local or minor; 5 is a global shock. |
| `horizon` | `now`, `weeks` or `months`: when the business impact lands. |
| `confidence` | 0–1: reported facts 0.75–0.95; inferred links 0.4–0.7; projections 0.3–0.6. |
| `sectors` | 1–3 of energy, agri-food, manufacturing, logistics-trade, finance, tech, health, real-estate, consumer. |
| `at` | Where it happened: a region id (country `region:in`, state `region:in-gj`, city `region:in-gj.surat`) or an infrastructure id. Look ids up in `gazetteer.json` and `entities/`. |
| `mentions` | Other ids the story is about: regions, commodities, organisations, infrastructure, policies, sectors. |
| `age_hours` | Events only. Spread them across 0–720 (30 days); put one or two under 1 hour so the "new" pulse shows. |
| `sources` | Events only, 1–60: how many outlets covered it. Bigger stories have more. |

## Link types

| Type | From → to | Meaning |
| --- | --- | --- |
| `reported` | event → event | A source says A caused B. Confidence 0.75–0.95. |
| `inferred` | event → event | A plausible link the model proposes. Confidence 0.4–0.7. |
| `projected` | event → projected story | A possible future impact via dependencies. Confidence 0.3–0.6. |
| `conditional` | event → projected story | Happens only if a forecast resolves a certain way. Needs `forecast` and `outcome` (YES/NO). Always give both branches: one link with YES and one with NO, each to a different projected story. |

Links may point to stories in other storylines (cross-border cascades are encouraged), but only to stories that already exist in committed files.

## Forecasts

Each `forecast` has:
- a `location` (where its ring sits on the globe)
- `about` (the ids it concerns; put the home region first)
- `end_in_days`
- a `resolution_rule`
- a `history`:
  - `start` and `end` probabilities (0.01–0.99)
  - optional sharp `moves`, for example `{days_ago: 0.5, delta: 0.12}` for a 12-point move in the last day; give about a third of forecasts a move of 10 points or more within 1 day
  - `volume` and `liquidity`; use low values (volume < 5,000 or liquidity < 1,000) for "thin market" examples

Allowed categories are economy, finance, policy, politics, geopolitics, trade, tech, commodities and energy. Never sports, entertainment or celebrities.

## Indicators

`entities/indicators.yaml` describes KPI series that the build generates deterministically. For example:

```yaml
- {id: indicator:in-cpi, name: Inflation, subject: region:in, unit: "%", frequency: monthly, higher_is: worse, points: 18, start: 5.1, end: 4.2, volatility: 0.3, decimals: 1}
```

Give each country with stories up to four KPIs, chosen from inflation, policy rate, currency per USD, fuel price, power demand and manufacturing PMI. Use plausible recent levels. Commodity prices attach to the commodity (`subject: commodity:crude-oil`).
